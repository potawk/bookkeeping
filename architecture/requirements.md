# 簿記を利用した家計簿アプリ 要件定義書

## 1. サービス概要

### 1.1 サービス名

Home Bookkeeping

### 1.2 コンセプト

**「家計を“決算”しよう」**

企業会計と同じ複式簿記で記帳し、お金の流れ（損益計算書）も、資産・負債の全体像（貸借対照表）もまるごと見える Web 家計簿アプリ。

### 1.3 ターゲットユーザー

- 20〜50代の会社員・公務員・フリーランス／副業をしている人
- 簿記3級〜2級程度の知識がある人、または簿記を勉強中で実生活でも使ってみたい人
- 家計の管理を自分でしっかり行いたい一人暮らし〜夫婦世帯
- クレジットカード払い、スマホ決済、ローン返済、NISA・iDeCo 等の投資、立替金など、現金以外の取引が増えている人
- 「収支」だけでなく「財産の状態（純資産）」を把握したくなっている人

### 1.4 解決したい課題

| 課題 | 解決策 |
|---|---|
| 単式の家計簿では「お金の流れ（フロー）」しか分からず、「財産の状態（ストック）」が見えない | 全取引を借方・貸方の仕訳で記録し、貸借対照表（資産・負債・純資産）と損益計算書（収益・費用）を自動で作成する |
| カード払いやローン返済で、支出の発生と口座からの引落しの時期がずれ、収支が実態と合わない | 「未払金」「借入金」「立替金」などの科目で、発生時点で費用を計上し、引落し時に負債を減らす形で記帳する |
| 期間ごとの比較や推移が分かりにくい | 開始日・終了日を自由に指定した損益計算書と、任意の基準日の貸借対照表を作成できるようにする |
| 既存アプリの科目が固定されていて自分の家計に合わない | 勘定科目と、科目ごとの補助科目（例：普通預金→○○銀行／△△銀行）を自由に追加・編集・削除できるようにする |

### 1.5 提供価値

- **正確性**: 複式簿記による記帳で、収支と残高が必ず一致する
- **全体像の把握**: 任意期間の損益計算書と任意時点の貸借対照表で、家計の「経営成績」と「財政状態」が分かる
- **自由な科目設計**: 勘定科目・補助科目を自分の家計に合わせて設計できる
- **どの端末からでも**: ブラウザで動くため、スマホでも PC でも同じ帳簿を使える

### 1.6 類似サービスとの違い

- Android アプリ「複式家計簿」の考え方に近いが、端末に依存せず PC・iPhone を含むブラウザから利用できる
- 事業者向け会計ソフト（freee 会計など）より機能を家計向けに絞り込み、事業用の科目や画面を持たない
- 自動連携型の家計簿アプリ（マネーフォワード ME など）と異なり、単式ではなく仕訳から始める複式簿記で、B/S 視点と期間指定の決算ができる

### 1.7 利用シーン

- 買い物や支払いをした直後に、スマホからその日の仕訳を入力する
- 1日の終わりや週末に、レシートやカード明細を見ながら PC でまとめて記帳する
- 月末に損益計算書で支出を振り返り、貸借対照表で純資産の増減を確認する
- 給料日やカード引落日に、通帳・アプリの残高と帳簿上の残高を照合する
- 年末（または年度末）に1年間の損益計算書と期末の貸借対照表を作り、家計の「決算」をする
- 簿記を学習中の人が、実生活の取引で仕訳の練習をする

### 1.8 利用の流れ

1. メールアドレス＋パスワードでサインアップする（標準の勘定科目が自動で作成される）
2. 期首残高入力画面で、利用開始日時点の資産・負債の科目と金額を入力する（差額は純資産（元入金）として自動計算される）
3. 必要に応じて勘定科目・補助科目を追加・編集・削除する
4. カレンダーで日付を選び、その日の仕訳を登録する
5. 仕訳一覧から仕訳を確認・編集・削除する
6. 期間を指定して損益計算書を、基準日を指定して貸借対照表を確認する
7. 利用を終えたらログアウトする

## 2. 機能要件

### 2.1 主要機能

### 機能1: 仕訳の記帳（カレンダー・仕訳）

- 月間カレンダーで日付を選択し、その日の仕訳一覧を表示する
  - 年月の切替（前月／翌月、今日ボタン）
  - 仕訳がある日を強調表示し、仕訳件数をバッジで表示する
  - 当月の収益合計・費用合計・当期純損益を表示する
- 日別仕訳一覧
  - 選択日の仕訳一覧（借方科目・貸方科目・補助科目・金額・摘要）
  - 前日／翌日への切替
- 仕訳の登録・表示・編集・削除
  - 入力項目：日付、借方（勘定科目・補助科目・金額）、貸方（勘定科目・補助科目・金額）、摘要
  - 選択した勘定科目に応じて補助科目の選択肢を絞り込む
  - 借方金額を貸方金額へ自動反映する
  - 貸借差額を表示し、借方合計と貸方合計が一致しない場合は保存できない
  - 削除時は確認ダイアログを表示する

### 機能2: 勘定科目・補助科目の管理

- 勘定科目は「資産・負債・純資産・収益・費用」の5区分
- 勘定科目の登録・一覧・詳細・編集・削除
  - 一覧は区分タブで切り替え、科目名と補助科目数を表示する
  - 科目名の重複はユーザー内で不可
- 補助科目の登録・一覧・編集・削除（勘定科目詳細画面で行う）
  - 補助科目名の重複は同一勘定科目内で不可
- 仕訳で使用中の勘定科目・補助科目は削除できない（勘定科目は区分の変更もできない）
- 新規登録時に標準の勘定科目を自動作成する

### 機能3: 期首残高の入力

- 利用開始時点（期首日）の資産・負債の科目と金額を入力する
- 補助科目単位での入力も可能（補助科目は任意）
- 資産合計・負債合計を表示し、純資産（元入金）＝資産合計－負債合計を自動計算する
- 期首残高の登録・表示・更新
- 期首残高は通常の仕訳とは別の専用データ・専用画面で持つ

### 機能4: 決算書（レポート）

- **損益計算書（P/L）**
  - 開始日・終了日を指定し、期間内の仕訳を集計する
  - プリセット：今月、先月、今年、昨年
  - 収益・費用の科目別金額、収益合計、費用合計、当期純損益を表示する
  - 補助科目別の内訳を展開表示できる
- **貸借対照表（B/S）**
  - 基準日を指定し、期首残高＋基準日までの仕訳を集計する
  - プリセット：今日、先月末、昨年末
  - 資産・負債の科目別残高、純資産（元入金＋利益剰余金）、資産合計、負債・純資産合計を表示する
  - 補助科目別の内訳を展開表示できる
- 決算書は保存せず、表示のたびに保存済みの仕訳から集計する

### 2.2 必須機能（主要機能を支える最小限の機能）

### ユーザー認証

- メールアドレス＋パスワードでのサインアップ・ログイン・ログアウト（ソーシャルログインには未対応）
- サインアップ時はメールアドレスの確認を行わず、登録直後から利用できる
- セッション管理（未ログインでログイン必須ページを開いた場合はログイン画面へリダイレクト）

### ユーザー情報管理（マイページ）

- ユーザー情報（ユーザー名・メールアドレス・登録日）の表示
- ユーザー名・メールアドレスの編集
- 期首残高入力画面へのリンク、ログアウト

### データの分離

- 全データをユーザーごとに分離し、本人のデータのみ参照・操作できる

## 3. 非機能要件

### 3.1 パフォーマンス

- 仕訳の登録・決算書の表示が、利用者が待たされたと感じない速さで完了すること
- 決算書は保存済みの仕訳から都度集計するため、仕訳件数が増えても実用的な速度で表示できること

### 3.2 ユーザビリティ

- レスポンシブ対応（スマホ・PC の両方で使える）
- ナビゲーションメニューは、スマホでは画面下部のフッター、PC ではサイドバーに表示する
- 共通ヘッダーにサービス名／ロゴとログアウトボタンを表示する
- 入力エラーは項目ごとに日本語で表示する
- 送信中はローダーを表示し、二重送信を防ぐ
- デザインは `.claude/design_system.md` に従う（白背景、青を軸にした配色、アクセシビリティ重視、タッチターゲット 44px 以上）

### 3.3 セキュリティ

- HTTPS 通信
- Supabase の Row Level Security（RLS）により、データベースのレベルで本人のデータのみ参照・操作できるようにする
- サーバー側でもログインユーザーを検証してからデータを操作する
- API キーなど環境依存の値は環境変数で管理し、リポジトリに含めない

## 4. 複式簿記の詳細仕様

### 4.1 勘定科目の区分と残高の計算

| 区分 | 増加する側 | 残高の計算 | 表示する決算書 |
|---|---|---|---|
| 資産 | 借方 | 期首残高＋借方合計－貸方合計 | 貸借対照表 |
| 負債 | 貸方 | 期首残高＋貸方合計－借方合計 | 貸借対照表 |
| 純資産 | 貸方 | 貸方合計－借方合計 | 貸借対照表 |
| 収益 | 貸方 | 貸方合計－借方合計 | 損益計算書 |
| 費用 | 借方 | 借方合計－貸方合計 | 損益計算書 |

### 4.2 仕訳

- 1つの仕訳は「仕訳」（日付・摘要）と、複数の「仕訳明細」（貸借区分・勘定科目・補助科目・金額）で構成する
- 画面は借方1行・貸方1行で入力するが、データ構造は複合仕訳（借方・貸方が複数行）に拡張できる形にしておく
- 借方明細の金額合計と貸方明細の金額合計が一致しなければ保存できない
- 金額は1以上の整数（円）、摘要は200文字以内（任意）

### 4.3 期首残高

- 期首残高の純資産（元入金）は、資産の期首残高合計－負債の期首残高合計で計算する
- 金額は0以上の整数（円）
- 対象は資産・負債の勘定科目のみ

### 4.4 損益計算書の集計

- 開始日〜終了日（両端を含む）の仕訳明細を、収益・費用の勘定科目ごとに集計する
- 当期純損益＝収益合計－費用合計（マイナスの場合は当期純損失）

### 4.5 貸借対照表の集計

- 基準日時点の資産・負債の残高＝期首残高＋期首日から基準日までの仕訳明細の増減
- 純資産＝元入金（期首残高から計算）＋利益剰余金
- 利益剰余金＝期首日から基準日までの収益合計－費用合計
- 資産合計と負債・純資産合計は必ず一致する

## 5. 技術仕様

- **フロントエンド**: Next.js 16（App Router）、React 19、TypeScript（strict）、Tailwind CSS v4
  - Tailwind CSS は Turbopack のローダー（`@tailwindcss/turbopack`）で処理し、PostCSS の設定ファイルは使わない
  - 配色は Tailwind の標準ユーティリティクラスのみを使い、独自 CSS は極力定義しない
- **バックエンド**: Next.js の Server Actions・Server Components
- **データベース**: Supabase（PostgreSQL）
  - クラウドの Supabase プロジェクトを使用する（Docker は使わない）
  - スキーマ変更はマイグレーションファイルで行い、Supabase CLI（`npx supabase db push`）で反映する
- **認証**: Supabase Auth（メールアドレス＋パスワード）、`@supabase/ssr` による Cookie でのセッション管理
- **ホスティング**: Vercel（Supabase は開発時と同じプロジェクトを使う）
- **Lint**: ESLint（eslint-config-next）
- **テスト**: テストフレームワークは未導入

## 6. 画面構成

### 6.1 公開ページ（未ログインユーザー向け）

ログイン済みの場合は、カレンダー画面へリダイレクトする。

- **トップページ** (`/`): サービス名／ロゴ、キャッチコピー、アプリの特徴の説明、ログイン・新規登録ボタン
- **ログイン** (`/signin`): メールアドレス・パスワードでのログイン
- **新規登録** (`/signup`): ユーザー名・メールアドレス・パスワード・パスワード（確認）での登録。登録後は期首残高入力画面へ移動する

### 6.2 認証必須ページ（本人のデータのみ）

未ログインの場合は、ログイン画面へリダイレクトする。

| まとまり | 画面 | URL |
|---|---|---|
| 初期設定 | 期首残高入力 | `/opening-balances` |
| 仕訳 | カレンダー（ホーム） | `/calendar` |
| 仕訳 | 日別仕訳一覧 | `/calendar/[date]` |
| 仕訳 | 仕訳作成 | `/journals/create?date=[date]` |
| 仕訳 | 仕訳詳細 | `/journals/[id]` |
| 仕訳 | 仕訳編集 | `/journals/[id]/edit` |
| 勘定科目 | 勘定科目一覧 | `/accounts` |
| 勘定科目 | 勘定科目作成 | `/accounts/create` |
| 勘定科目 | 勘定科目詳細（補助科目の追加・編集・削除を含む） | `/accounts/[id]` |
| 勘定科目 | 勘定科目編集 | `/accounts/[id]/edit` |
| レポート | 損益計算書 | `/reports/pl` |
| レポート | 貸借対照表 | `/reports/bs` |
| その他 | マイページ | `/mypage` |

### 6.3 共通コンポーネント

- **ヘッダー**: サービス名／ロゴ、ログアウトボタン（認証必須ページ）
- **ナビゲーションメニュー**: カレンダー、勘定科目、レポート、マイページ（スマホはフッター、PC はサイドバー）

## 7. データ項目

| データ | 主な項目 | 制約 |
|---|---|---|
| ユーザー | ID、ユーザー名、メールアドレス、パスワード、作成日時、最終ログイン日時 | ユーザー名は20文字以内、メールアドレスはユニーク、パスワードは半角英数字8文字以上 |
| 勘定科目 | ID、科目名、区分、表示順、作成日時、更新日時 | 科目名は20文字以内でユーザー内ユニーク、区分は5区分のいずれか |
| 補助科目 | ID、勘定科目ID、補助科目名、表示順 | 補助科目名は20文字以内で同一勘定科目内ユニーク |
| 期首残高 | 期首日、勘定科目、補助科目（任意）、金額 | 勘定科目は資産・負債のみ、金額は0以上の整数 |
| 仕訳 | ID、日付、摘要、作成日時、更新日時 | 摘要は200文字以内（任意） |
| 仕訳明細 | ID、仕訳ID、貸借区分、勘定科目ID、補助科目ID（任意）、金額 | 貸借区分は借方・貸方のいずれか、金額は1以上の整数 |

## 8. 対象外とする機能

- 銀行口座・クレジットカード・電子マネーとの自動連携（自分の手で仕訳を入力することで家計の理解を深めることを重視する）
- レシート撮影による自動読み取り（OCR）
- 単式簿記の「簡易入力モード」（複式簿記に特化してコンセプトを尖らせる）
- 確定申告書や青色申告決算書など、税務申告書類の作成
- 消費税の計算や源泉徴収などの税務処理
- 節約記事やポイント情報などのコンテンツ配信、広告表示
- SNS のような他ユーザーとの共有・交流機能

## 9. 将来の拡張候補（初期リリースには含めない）

- 複合仕訳（借方・貸方が複数行になる仕訳）の入力画面
- よく使う仕訳のテンプレート登録、毎月の繰り返し仕訳の自動登録
- 仕訳帳・総勘定元帳・試算表の表示
- グラフ表示（純資産の推移、月別の収益・費用の推移、費用の内訳）
- 前月比・前年比の比較、予算と実績の比較
- 仕訳の検索・絞り込み
- CSV のエクスポート／インポート、決算書の PDF 出力
- 簿記初心者向けの仕訳ガイド
- 家族での帳簿共有、複数帳簿の管理
- PWA 対応、ダークモード

## 10. 未決定事項

- 標準で用意する勘定科目テンプレートの内容
- 期末の繰越処理を行うかどうか（貸借対照表は利益剰余金を都度計算するため、繰越処理なしでも作成できる）
- 会計年度の開始月をユーザーが任意に設定できるようにするか
- グラフ機能をどこまで実装するか
- 無料で公開するか、将来的に有料プランを設けるか
